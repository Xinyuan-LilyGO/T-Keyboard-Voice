# Factory

[English](README.md) | **简体中文**

T-Keyboard Voice V0.3 整机测试固件，包含 **18 项测试、五屏界面、按键导航和 USB 串口控制**。入口为 `Factory.ino`，主程序在同目录 `Factory.cpp`，硬件驱动复用仓库 `src/`。

> 本文的「正确现象」是依据当前代码整理的检查目标，不是已经完成实机验收的记录。自动 `PASS` 只说明该项目的软件条件满足；声音、显示、接口和低功耗仍需实际观察或测量。

## 1. 测试前准备

- T-Keyboard Voice V0.3（ESP32-S3 N16R8）、可传数据的 USB 线和电脑。
- 符合板卡规格、极性正确的测试电池；不接电池可以做部分测试，但第 2 项会报告 `FAIL / Battery not connected`。
- 两只正确连接的扬声器、耳机；首次播放不要贴近耳朵。
- 用于 CN5 的兼容外接麦克风/音源及匹配插头，按硬件要求接入，不要接入不明电平信号。
- 一个 3.3 V 逻辑 I2C 外设，地址不得与板载 `0x10`、`0x34`、`0x40` 冲突。
- 3.3 V USB-TTL 对测设备，或用于 CN3 TX/RX 回环的跳线。

**改接线前断开 USB 和电池；deep sleep 不等于断电。** CN3 不可接 RS-232 或 5 V TTL，不可把两个输出端直接并接。详细接线见 [引脚表](../../docs/pinmap.md#简体中文)。

## 2. 编译、烧录与串口

以下命令均在**仓库根目录**执行。

### PlatformIO

```bash
pio run -e factory
pio run -e factory -t upload
pio device monitor -b 115200
```

需要指定端口时，上传追加 `--upload-port COMx`，串口监视器追加 `-p COMx`；将 `COMx` 替换为实际设备端口。

VS Code 可用项目的 **Ctrl+Shift+B** 任务选择 `factory`，避开扩展缓存的任务列表。关于 `reading 'id'` 异常和项目状态栏按钮，见 [VS Code 排查说明](../../docs/vscode_troubleshooting.md#简体中文)。

### Arduino IDE

安装官方 **esp32 3.3.11** 和所需库，选择 **ESP32S3 Dev Module、16 MB Flash、OPI PSRAM、Hardware CDC and JTAG、USB CDC On Boot Enabled**。打开 `Factory.ino`，同目录的 `Factory.cpp` 和 `build_opt.h` 必须保留。完整分区及菜单设置见 [Arduino 使用说明](../../docs/arduino_ide.md#简体中文)。

### ESP-IDF

先进入已导出的 **ESP-IDF 5.5.6** 环境。该入口使用官方 Arduino 组件，不是纯 ESP-IDF 驱动移植。

```bash
python scripts/prepare_dependencies.py
idf.py -C idf -D IDF_TARGET=esp32s3 -D VOICE_EXAMPLE=Factory -p COMx build flash monitor
```

将 `COMx` 换为实际端口；ESP-IDF 监视器用 `Ctrl+]` 退出。不要把之前选择的其他 Demo 当作 Factory 烧录。详见 [ESP-IDF 使用说明](../../docs/esp_idf.md#简体中文)。

三种入口都使用 **115200 波特率的 USB CDC 控制台**。串口命令须以换行结束，选择 LF 或 CRLF；CN3 UART0 不是控制台。USB 重新枚举后可能需要重新选择端口。不同构建入口的分区方案不同，切换时不要混用旧 bootloader、分区表和新应用。

正常复位和启动时释放 KEY5，避免 GPIO0 使设备进入下载模式。

## 3. 上电后应该看到什么

1. 串口输出 `T-Keyboard Voice V0.3 board support`、`[POWER] boot=...`、`[MEMORY] PSRAM: ... bytes`，随后输出 `T-Keyboard Voice V0.3 factory hardware test`、帮助和 I2C 扫描结果。N16R8 应识别约 8 MB PSRAM，不能为 0。
2. **启动只自动执行第 1 项，不是自动完成全部 18 项。** PMIC 与所需电源轨初始化成功时，第 1 项为 `PASS`；其余尚未执行的项目为 `WAIT`，这是正常现象。
3. 普通测试页面中：屏 1/5 是 KEY1/KEY5 导航箭头；屏 2 显示测试编号和名称；屏 3 显示结果；屏 4 显示操作提示和简短详情。电池、麦克风及显示测试有专用页面。
4. 五块屏和背光应正常工作，无持续黑屏、明显花屏或异常反复重启。屏幕上的详情会截短，完整原因以串口日志为准。

首次检查时，在 USB 控制台逐行发送：

```text
help
scan
power
status
```

Factory 已请求全部外设电源轨，板载器件正常时，扫描应能看到 ES8389 `0x10`、AXP2101 `0x34`、ES7210 `0x40`。有地址应答仍不等于音频、电源和接口功能全部通过。

## 4. 如何操作与记录结果

### 按键

| 按键 | 普通测试中的操作 |
| --- | --- |
| KEY1 / KEY5 | 上一项 / 下一项，首尾循环 |
| KEY2 | 重新执行当前项目；第 7 项改为切换 PA 并播放 |
| KEY3 单击 | 当前项目记为人工 `PASS` |
| KEY4 短按 | 当前项目记为人工 `FAIL` |
| KEY4 长按 3 秒后释放 | 请求并进入 deep sleep，不是真正关机 |

**切换项目会立即执行测试，不是只选中等待开始。** 第 12 项中 KEY2～KEY4 只作为被测输入，不执行上述重测/PASS/FAIL 操作；但 KEY1/KEY5 的导航仍有效，KEY4 长按休眠也仍需避免。

### 串口命令

| 命令 | 用途 |
| --- | --- |
| `help` / `?` | 打印帮助 |
| `run N` | 立即执行第 N 项，N 为 1～18，例如 `run 8` |
| `next` / `prev` | 执行相邻项目 |
| `pass` / `fail` | 为当前项目记录人工结果 |
| `status` | 列出本次运行全部 18 项的状态和详情 |
| `scan` | 扫描共享 I2C 总线；不会代替执行第 14 项 |
| `power` | 查看电源键、PMIC 寄存器和启动/唤醒诊断 |
| `mic` | 查看 ADC 寄存器及当前实时采样诊断，先进入第 8 或 16 项 |
| `run` | 连续执行全部项目；**不会逐项停下来等待人工确认** |

播放、录音、灯效和显示流程包含短时阻塞，普通按键或串口响应可能延后；等流程结束再操作。Factory 没有独立的串口 `sleep` 命令。

### 状态含义

| 状态 | 含义与处理 |
| --- | --- |
| `WAIT` | 尚未测试，不是失败，也不是通过 |
| `RUN` | 正在执行 |
| `PASS` | 软件条件满足，或操作者手工确认；必须结合项目判定范围理解 |
| `FAIL` | 软件检测失败或操作者判为失败，查看详情排查 |
| `CHECK` | 初始化/数据流程已完成，仍需人工听音、观察或测量；不是自动故障 |

普通结果页中 `PASS` 为深绿色、`FAIL` 为红色、`CHECK` 为橙色；`WAIT`/`RUN` 为蓝色。人工 `pass` 可以覆盖自动失败，不能因此掩盖故障；电池等自动刷新项目也可能再次更新结果。

**推荐逐项测试：**发送 `run N` → 观察或测量 → 确认正常后发送 `pass`，异常则发送 `fail` → 用 `status` 复查。不要盲发一串 `pass`。先完成普通功能项目并保存结果，最后再做第 3 项休眠/唤醒验证。

## 5. 全部 18 项：操作与正确现象

| 编号 / 项目 | 如何操作、正常应出现什么 | 当前固件的判定 |
| --- | --- | --- |
| 1 · AXP2101 / `run 1` | `0x34` 应答，PMIC 初始化与所需电源轨读回成功，五屏界面建立 | 自动 `PASS` / `FAIL`；不代替电压、电流实测 |
| 2 · 电池信息 / `run 2` | 接好电池，显示连接、电量、VBAT/VSYS、VBUS 和充电状态；接入/移除 USB 后信息应符合实际供电状态 | 自动；无电池为 `FAIL`，不是 PMIC 通信失败的同义词 |
| 3 · 电源键/休眠 / `run 3` | 长按 KEY4 3 秒再释放，显示/背光和 RGB 关闭、USB CDC 断开；通过 KEY4 或符合条件的 USB 插入重新启动 | `CHECK`，需人工及仪器验证；见下文 |
| 4 · ES8389 / `run 4` | 日志显示在 `0x10` 找到 Codec | 地址应答自动 `PASS`，不代表扬声器/耳机已正常 |
| 5 · ES7210 / `run 5` | 日志显示在 `0x40` 找到 ADC | 地址应答自动 `PASS`，不代表麦克风采样已正常 |
| 6 · 扬声器 / `run 6` | 立即播放内置测试音频，两只扬声器都应有清晰可辨声音，无明显失真、杂音或缺一路 | 数据发送成功后为 `CHECK`；必须听音确认 |
| 7 · PA / `run 7` | 初始 `PA: OFF`；单击 KEY2 切换到 ON 并播放，再单击切回 OFF 并播放；比较扬声器有声/静音 | `CHECK`；只比较扬声器，PA 不控制耳机静音 |
| 8 · 板载双麦 / `run 8` | 屏 3/4 显示 `MIC1 BOARD` / `MIC2 BOARD`；讲话时两路波形和 RMS 有响应，配合 `mic` 观察 | `CHECK`；不靠固定 RMS 阈值自动判灵敏度 |
| 9 · 耳机 / `run 9` | PA 关闭，耳机能听到测试音频，左右声道都正常 | `CHECK`；需人工确认耳机，不是检查扬声器 |
| 10 · 五屏 / `run 10` | 按配置屏序显示红/绿/蓝/白/黄及数字 1～5，约 1.8 秒后返回测试界面；不得缺屏、重号或明显花屏 | `CHECK`；错过显示过程可重测 |
| 11 · 背光 / `run 11` | 五屏白底，背光同步渐亮、熄灭，再全亮；不应只有个别屏随亮度变化 | `CHECK`；共用 GPIO1，低电平有效 |
| 12 · 五键 / `run 12` | 各键产生按下/释放日志，五键都记录后 `seen mask` 为 `0x1F` | 掩码完整时自动 `PASS`；掩码在本次运行累计 |
| 13 · WS2812 / `run 13` | 全部 14 颗灯完成 RGBW 纯色、逐颗追逐和位置图案；无缺灯、错色或中途断链 | `CHECK`；必须逐颗观察 |
| 14 · CN4 I2C / `run 14` | 接入外设后，扫描出现一个非 `0x10/0x34/0x40` 的地址；同时核对板载器件未缺失 | 检测到外部地址才自动 `PASS`；没有外设时 `FAIL` 是当前规则的预期结果 |
| 15 · CN3 UART / `run 15` | 对端收到 `T-KeyboardVoice QWIIC UART0 test`；对端发回内容后，USB 控制台出现 `[QWIIC UART0 RX]` | `CHECK`；单独的 sent 日志不证明对端接收或 RX 正常 |
| 16 · 外接 MIC/AEC 参考 / `run 16` | 屏 3/4 显示 `MIC3 AUX` / `MIC4 AEC`；向 CN5 提供已知音频，MIC3 波形/RMS 应响应，MIC4 结合参考信号检查 | `CHECK`；此模式播放静音，MIC4 安静不能单独判为故障 |
| 17 · MIC3 录放 / `run 17` | 进入项目即录制约 1 秒，随后两只扬声器播放刚输入 CN5 的内容 | `CHECK`；听到实际录音才算确认，不是听到噪声就通过 |
| 18 · 板载双麦录放 / `run 18` | 进入项目即对板载麦讲话约 1 秒，随后听到两路混音后的录音从两只扬声器播放 | `CHECK`；不是 MIC1/MIC2 分别独占左右扬声器 |

测试音频资源实际为 `assets/66_stereo_48k.wav`，48 kHz、16-bit 双声道；部分沿用的界面提示仍写作 `66.wav`，指的是这份内置测试音频，无须另行上传文件。

## 6. 容易误判的项目

### 电池、电流与充电

第 2 项约每秒刷新。当前代码检查电量 0～100%、VBAT 2500～5000 mV、VSYS 2500～5500 mV、ADC 读取有效、充电状态码及设定、PMIC 故障等条件。这些是软件粗检范围，**不是电池或充电规格书的合格标准**。不接电池会显示 `Battery not connected` 并判 `FAIL`，不能将它当作完整电源测试通过。

`IBAT/IBUS: N/A` 是正常的能力边界；AXP2101 不提供这里需要的实时电流测量。`ICC` 是充电设定值，不是实测电流；是否正在充电还取决于电池、VBUS 和实际充电阶段。

### 五键

第 12 项中，可先短按 KEY2、KEY3、KEY4，再按 KEY1 离开到第 11 项，等背光流程结束后按 KEY5 返回第 12 项；同一次运行累计识别全部五键后，应看到 `0x1F` 和 `PASS`。若此前已经按过部分键，掩码可能一开始就有相应位。不要把 KEY4 长按成休眠。


### 麦克风、AEC 与录音

- 进入 `run 8` 或 `run 16`，等有实时采样后再发送 `mic`。在其他项目看到 `No live samples` 不代表 ADC 一定损坏。
- 用等距离、稳定声源比较板载双麦，并重复读取。波形会自动缩放；短窗口 RMS 或单次波形高度不是量产灵敏度指标。
- MIC3 是外接输入，MIC4 是 AEC 参考；读取参考不等于实现回声消除。第 16 项关闭播放，参考可能没有有效激励，不要求它与 MIC3 波形相同。
- CN5/GPIO6 的插入检测仅作提示，某些 TRRS 插头不改变它；不能仅凭 `AUX UNPLUGGED` 判外接采集失败。
- 第 17/18 项是**录制 1 秒后回放**，不是实时监听。进入项目时就开始准备并录音；回放结束后如需实时波形，重新执行 `run 8` 或 `run 16`。
- `capture timeout`、`recording buffer allocation failed`、`READ FAILED` 或持续削波都需排查时钟、供电、PSRAM、接口和输入电平，不应直接人工覆盖为通过。

### 休眠与唤醒

1. 先保存串口 `status` 和观察记录，再发送 `run 3`。
2. KEY4 持续按住至少 3 秒，收到提示后释放；只按住不释放，不算完成休眠操作。
3. 观察屏幕/背光、RGB 和音频退出，USB CDC 断开；用仪器测量低功耗，不能仅凭黑屏认定休眠电流合格。
4. 按 KEY4 唤醒，必要时保持按下直至设备开始启动，再释放；重连 USB 串口并执行 `power`，应能看到相应的 KEY4 唤醒来源。
5. 验证 USB 插入唤醒时，需由电池维持待机、VBUS 原先不在位，再插入 USB，检查 `USB/VBUS wake`。持续插着 USB 不会再触发插入事件；**USB-only 断开 USB 后再插入属于重新上电，不能当作电池维持的插入唤醒测试**。

deep sleep 保留 DCDC1，不是真正 PMIC 关机。唤醒会重新执行启动流程，从第 1 项开始；测试结果保存在 RAM，重启/深睡唤醒后不保留。不要把新启动的第 1 项 PASS 当成第 3 项通过。需要重新记录第 3 项时，选 `run 3` 再结合刚才的实际观察人工确认。完整供电条件和失败恢复说明见 [供电与休眠](../../docs/power_and_sleep.md#简体中文)。

## 7. 常见问题与最终记录

| 现象 | 先检查 |
| --- | --- |
| USB 串口无输出或命令不执行 | 数据线、实际运行态端口、115200、换行设置、USB CDC 选项；不要连错 CN3 |
| `[MEMORY] PSRAM` 为 0 或录音缓冲分配失败 | N16R8 板型和 OPI PSRAM 设置，不要继续把录放结果当有效测试 |
| 第 1 项失败、五屏不显示 | PMIC `0x34`、供电与电源轨读回，再检查 ALDO3、共享 SPI/复位和各 CS；勿占用 PSRAM 的 GPIO35～37 |
| 第 4/5 项通过但没有声音/采样 | I2C 应答只是前提；继续检查音频电源、I2S 时钟、PA、扬声器/耳机/麦克风接线 |
| 第 14 项失败 | 先确认是否真的接入了非板载地址的外设，再检查供电、SDA/SCL、地址冲突 |
| 第 15 项无回传 | CN3 TX GPIO43 / RX GPIO44，3.3 V TTL、115200 8N1、共地、TX/RX 交叉；可仅短接本板 TX/RX 做回环，勿并接多个驱动输出 |
| 休眠取消或无法唤醒 | 查看 `[POWER] deep-sleep aborted` 等原因，检查 KEY4 释放、GPIO12/21、PMIC IRQ、供电条件；不要只依据 USB 是否重连判断 |

最后执行 `status`，逐项核对 18 项；有 `WAIT` 或 `CHECK` 就不能称为全部验证通过。即使全是 `PASS`，也要结合原始日志、人工观察和仪器记录，防止手工覆盖掩盖失败。当前固件不自动导出或持久保存验收报告，请记录板卡/硬件版本、固件及构建入口、日期、操作者、各项观察和电压/电流实测值。

更多依据见 [Factory 测试指南](../../docs/factory_test_guide_cn.md#简体中文)、[音频说明](../../docs/audio.md#简体中文) 和 [软件验证记录与实机边界](../../docs/validation.md#简体中文)。
